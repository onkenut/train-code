# 项目规则 - 全 AI 生成项目集

## 项目性质

这是一个**多分支项目集**，仓库的每个分支（`main` 除外）都是一个独立的完整项目。  
`main` 分支本身不包含任何项目的源代码，仅保留：
- 本规则文件
- 根级 `.gitignore`
- 根级 `README.md`（项目集总览）

假如有子项目：**TeamBrain**、**DungeonScrip** 等，它们均以独立分支的形式存在。

## 新建项目规则

- **禁止在 `main` 分支直接创建代码文件**。任何新项目的所有文件必须在一个以项目名命名的独立分支中完成。
- 新建分支命名应简洁、有意义，使用 PascalCase 或 kebab-case（如 `MyProject` 或 `my-project`），与已有项目分支风格保持一致。
- 每个新项目分支**必须**包含该项目的 `README.md`，内容至少包括：项目简介、技术栈、如何运行。
- 项目分支的初始创建应基于 `main` 分支检出，以保证仓库结构一致：
  ```bash
  git checkout main
  git checkout -b 新项目名
  ```

## Git 规则

- **必须**在达到一定规模时主动执行 `git commit`（如：一个完整功能模块完成、一组相关文件创建完毕、阶段性里程碑达成）。
- commit 信息应简洁明了地描述变更内容。
- **禁止主动执行 `git push`**。仅当用户明确要求时才可推送。
- 每个项目分支应有合理的 `.gitignore`，排除编译产物、依赖包、数据库文件、环境配置等。
- 日常开发应在对应项目分支内进行，切换项目时：
  ```bash
  git checkout 目标项目分支
  ```

## 代码规范

- 遵循每个项目分支自身的技术栈和代码风格。
- 不要跨分支混用依赖或引入其他分支的文件（Git 分支间天然隔离）。
- 每个项目分支应保持独立、完整且可运行。
